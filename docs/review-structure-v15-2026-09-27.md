# 구조 정리 V15 R1 — 일일업무현황 확대 보기 기능 분리

검토 기준: `116fc3c6c2c46c9e92983d27aee29c8c5cbbd01c`.

## R1 재작성 근거

최초 V15 준비 후 다른 대화에서 오전회의 카드의 혼소율 마감자료 연동이 반영됐습니다. 이 변경은 메인 파일과 `closedcards=20260927-v1` 캐시 매개변수를 함께 수정했습니다. V15의 이전 기준과 달라 설치기는 파일을 쓰기 전에 중단했습니다.

R1은 해당 변경을 포함한 최신 코드에서 동일한 확대 보기 함수만 다시 분리합니다. 사용자 로그에 나온 메인 파일 SHA-256 `6ed2203a92ad3c07ca09d184006b229c172631b0f379c9fab20f3409ff091e65`는 이 기준 커밋의 Windows CRLF 파일과 정확히 일치합니다. 내용을 확인하지 않은 파일을 허용하도록 검사를 완화하지 않았습니다.

마감자료 연동의 메인 코드, 추가된 별도 파일, API, 검사와 HTML 로더를 모두 보존합니다. 메인의 캐시 URL에서도 `closedcards=20260927-v1`을 유지합니다. 이전 중단에서는 변경된 파일이 없었으므로 별도의 원복 없이 R1을 적용할 수 있습니다.

## 목적과 범위

V14에서 업무일지 검색 결과 기능을 분리한 다음 단계로, 효율팀 일일업무현황의 **크게 보기·원래 크기 복귀** 기능을 별도 파일로 옮깁니다. 파일별 기능 경계를 만드는 작업이며 화면 디자인이나 사용 방법은 바꾸지 않습니다.

| 대상 | 변경 |
| --- | --- |
| `script.js` | 원래 확대 보기 설치 함수를 같은 위치의 설치 호출로 교체 |
| `maintenance/efficiency-daily-work-expanded-mode.js` | 기존 함수 전체를 그대로 이동 |
| `index.html` | 새 파일의 로더 추가, 메인 캐시 버전 갱신 |
| `tests/project-structure-v12.test.mjs` | 별도 파일의 캐시 버전이 모두 같아야 한다는 단언을 각각 존재하는지 확인하도록 조정 |
| `tests/project-structure-v15.test.mjs` | 확대·축소, 보관함 복원, 이벤트·초기화 순서 및 로더 검사 추가 |
| 이 문서 | 수정 근거, 의존 관계와 검증 범위 기록 |

V14 검색 파일과 URL은 그대로 유지합니다. CSS, 모바일 코드, 혼소율 계산, Agent, Excel, API, DB는 수정하지 않습니다. 혼소율 소요 시간 개선과 화면 디자인은 별도로 진행하는 작업입니다.

## 실행 시점과 함수 내용 보존

원래 설치 함수 `initializeEfficiencyDailyWorkExpandedModeFinal`은 메인 파일의 앞부분에서 클릭 이벤트를 등록합니다. 뒤쪽 기능의 초기화가 실패하더라도 이미 등록된 확대 버튼은 사용할 수 있도록 한 구조입니다.

새 파일은 엄격 모드의 classic script이며 `window.GSEfficiencyDailyWorkExpandedMode.install`을 정의하기만 합니다. 실행은 메인의 원래 위치에 남긴 `(0, window.GSEfficiencyDailyWorkExpandedMode.install)();`에서 합니다. 따라서 이벤트 등록 순서, 뒤쪽 초기화 오류 발생 시 동작, Promise 콜백과의 순서를 유지합니다. 새 파일을 읽는 순간 DOM을 조회하거나 이벤트를 등록하지 않습니다.

이동한 함수는 **4,849바이트**이며 분리 전후 바이트와 구문 트리가 같습니다. SHA-256은 `10fe3dc774e68f0cf2ef4a062cb6ef6b5a0040e6b0ec00046afe4d35199daddf`입니다. 나머지 메인 코드의 바이트와 1,143개 최상위 구문도 동일합니다. 함수에는 `this`, `eval`, `arguments` 참조가 없습니다. 새 전역 이름은 기존 코드에 없음을 확인했습니다.

스크립트 순서는 **V15 확대 보기 정의 → V14 검색 정의 → 메인 실행**입니다. 세 파일은 모두 `defer`로 읽고, V14 검색 정의와 메인 사이의 인접 관계를 유지합니다. 메인 내부에서는 확대 보기 설치가 앞부분에서, 검색 설치가 기존 끝부분에서 실행됩니다.

## 의존 관계와 기존 동작

| 의존 대상 | 용도 |
| --- | --- |
| `window`, `document`, `Element` | 전역 API, 위임 클릭 이벤트, 필요한 DOM 요소 조회 |
| `Boolean`, `String` | 확대 여부와 접근성 속성 값 변환 |
| `window.requestAnimationFrame` | 확대 후 용지 스크롤을 왼쪽 위로 이동 |
| `window.setEfficiencyDailyWorkExpandedMode` | 기존 외부 확대·해제 호출 경로 유지 |
| 기존 중복 설치 플래그 | 재설치 시 이벤트 중복 등록 방지 |

업무 계산·저장 함수나 인증 상태를 직접 참조하지 않습니다. 자동 행 높이와 줌 기능에서 관찰하는 확대 클래스도 그대로 유지합니다.

- 확대 전 날짜별 보관함의 표시 상태를 기억하고 복귀할 때 되돌립니다.
- 확대 버튼의 자식 요소를 눌러도 동작하며 해당 클릭의 기본 동작·전파를 차단합니다.
- 상단·하단 닫기 버튼은 확대를 해제한 뒤 기존 닫기 이벤트가 이어지도록 합니다.
- 화면 DOM이 나중에 만들어져도 위임 이벤트로 처리합니다.
- 기존 버튼 문구, 접근성 속성, 클래스 및 스크롤 인자는 유지합니다.

연속된 확대 호출의 상태 기록 방식이나 Esc·배경 클릭 처리 범위는 이번 분리에서 변경하지 않습니다. 이 패치로 혼소율 계산 시간이나 초기 다운로드 크기가 감소한다고 주장하지 않습니다.

## 검증과 적용

자동 검사는 실제 분리 파일을 VM에서 실행해 확대·복귀와 보관함 상태, 중첩 클릭, 두 닫기 버튼, 지연 DOM 생성, 누락 요소, 중복 설치, 후속 초기화 오류 및 이벤트 순서를 확인합니다. 기존 V12·V14 검사도 함께 실행합니다. 새 로더의 단일성·순서·캐시 URL과 웹 빌드 포함을 확인합니다.

전체 검사·웹 빌드·설치·원복·반영 검증의 구체적인 결과는 패키지의 `VERIFICATION.json` 및 `evidence/`에 기록합니다. 실제 회사 PC 브라우저나 Excel/DataPARC, 운영 API·DB를 호출한 검증은 아닙니다.

설치기는 검토한 파일인지 모두 확인한 뒤 백업·적용합니다. HTML은 새 로더 삽입과 메인 캐시 URL만 변환해 다른 화면 변경을 보존합니다. 전체 검사와 빌드가 통과한 뒤 검토한 6개 대상만 커밋·푸시하며, 관련 없는 staged·working 변경은 유지합니다. 적용 후 배포가 완료되면 브라우저에서 크게 보기, 원래 크기, 두 닫기 버튼 및 보관함 복원을 확인합니다.

후속 구조 정리 후보는 석회석 사용량 기능과 기능별 CSS입니다. 초기화·전역 의존과 스타일 적용 순서를 먼저 분석해야 합니다. 과거 백업·로그·설치 의존성의 Git 추적 정리, DB 마이그레이션·복구 절차, PDF·조회 실패 후 Excel 정리도 이후 과제로 남깁니다.
