# 혼소율 계산·마감 저장 검토 — 3차

기준: 2026-09-24, 앞선 접근 보호 2차 패치 적용본. 신규 패치 적용 대상은 11개 파일이며, 기존 조회 계약 파일 1개도 일치 여부를 검사합니다.

## 변경 내용

1. **서버가 마감 계산을 다시 검증합니다.** 기존에는 완료 상태와 날짜만 확인한 뒤 브라우저의 결과·요약값을 그대로 저장했습니다. 이제 완료된 서버 조회 원본의 요청 ID, 하루 전체 기간, 10개 TAG 및 경계값 계약을 확인하고 공용 계산 코어로 연료 사용량·열량·혼소율을 재계산합니다. 화면과 계산값이 다르면 저장하지 않습니다. 요약값과 계산 메타데이터는 서버에서 생성합니다.
2. **동시 수정과 삭제 충돌을 막습니다.** 최초 저장은 날짜 중복을 원자적으로 막고, 갱신·삭제는 사용자가 확인한 revision 및 version을 검증합니다. 마지막 SQL에도 기존 revision·스냅샷·갱신 시각 조건을 넣습니다. 삭제 후 다시 생성된 1차 자료도 새 저장 식별자로 구분합니다. 충돌 시 자동으로 최신 자료를 덮어쓰지 않습니다.
3. **실제 계산 입력값을 기록합니다.** 브라우저의 최근 저장 상태와 현재 입력란이 다를 수 있으므로, 화면이 계산에 사용한 발열량·보정계수·유기성·축분 입력을 마감에 기록합니다. 별도의 기준값/수기값 저장 기능은 그대로입니다.
4. **혼소 조정의 누락값 처리를 보강합니다.** 석탄·바이오 등 필수 연료가 누락된 결과를 0으로 바꿔 조정하지 않습니다. 일반 계산과 조정 계산의 `ratios.organic`은 모두 유기성+축분 합계 비율을 의미합니다. 상세 `fuelRatios.organic`은 유기성 단독 비율을 유지합니다.
5. **마감 목록을 최신 상태로 표시합니다.** 새로고침과 저장 알림 시 상세 캐시를 지웁니다. 빠른 월 이동에서 이전 응답이 현재 월을 덮지 않도록 합니다. 월별 서버 조회를 추가해 최신 366일보다 오래된 자료도 선택한 월로 조회합니다.
6. **자동 저장 실패를 화면에 표시합니다.** 자동 마감은 계산 버튼을 누를 때 확인한 버전을 사용합니다. 날짜나 로그인 사용자가 바뀌면 대기 중인 저장을 취소합니다. 수동 갱신 확인과 삭제도 확인한 버전을 전달합니다.

## 유지한 계산 기준

- 하루 계산은 한국 시간 00:00~다음 날 00:00, 경계 취득용 조회 끝은 다음 날 00:01입니다. 조회 여유 1분을 하루 사용량에 더하지 않습니다.
- 수기 유기성·축분 빈칸은 기존 화면 정책대로 계산에만 0을 적용합니다. 원래 입력은 `null`로 보존하고 `manualBlankPolicy`에 이 정책을 기록합니다. 실제 입력 0과 미입력은 저장 자료에서 구별됩니다.
- DataPARC 중간 품질 공백은 기존 계약이 허용하는 경계값 조건을 만족하면 계산하되 품질 경고를 함께 보존합니다.
- 월평균은 항목별 유효한 일별 값의 산술평균입니다. 누락은 제외하고 실제 0은 포함합니다. 월 총 투입열량으로 가중한 혼소율로 바꾸지 않았습니다. 평균 행 설명에 현재 기준을 명시했습니다.
- Bio 수동 이동, 최종량 직접 수정, 최대량 자동 조정은 기존 공용 계산을 사용하며 서버도 같은 규칙으로 검증합니다.

## 기존 자료와 설치 범위

- 기존 마감 자료는 자동으로 재계산하거나 갱신하지 않습니다. 읽기 방식과 기존 필드를 유지합니다. 새 마감·명시적 갱신부터 검증 버전 3을 적용합니다.
- 기존 데이터베이스 컬럼을 그대로 사용합니다. 새 테이블·컬럼 마이그레이션은 없습니다. 원래 API의 테이블 존재 확인 동작은 유지합니다.
- 오래 열린 화면에서 version 없이 저장/삭제하면 428 응답과 새로고침 안내를 표시합니다. 배포 후 Ctrl+F5로 새 코드가 로드돼야 합니다.
- Agent/Excel 실행 코드와 회사 PC 설정은 수정 대상이 아닙니다. Agent 재시작은 필요하지 않습니다.
- 설치 도구는 Git·배포·운영 DB·실행 프로세스를 조작하지 않습니다. 검토된 대상의 원본 또는 수정본 해시만 허용하며 LF/CRLF 차이는 검토한 바이트 변형에 한해 허용합니다.

## 검증

- `project-hardening-v1.test.mjs` 13개 + `project-access-v2.test.mjs` 17개 + `project-cofiring-v3.test.mjs` 19개: **49개 통과**.
- 새 API 검사: 무인증/비활성 차단, 변조된 수치와 설정, 원본 기간 불일치, 정상 품질 공백, 세 가지 혼소 조정, 누락/0, 실제 입력값 기록, 이중 저장, 오래된 버전 삭제, 삭제 후 재생성, 월별 조회, 잘못된 JSON과 바이트 용량 제한, DB 오류 시 보존.
- JSDOM에서 실제 마감 모듈을 실행한 6개 동작 검사 통과: 자동 저장의 버전·입력값, 충돌 표시, 날짜·사용자 변경 취소, 수동 갱신 확인, 월별 캐시/삭제, 늦게 도착한 월 응답 차단. 실제 브라우저 시각 검사는 아닙니다.
- 서버 모듈은 esbuild 0.28.2로 ESM 번들 생성과 로딩을 확인했습니다. 운영 Cloudflare 배포 검사는 사용자 저장소에서 푸시한 후 별도로 수행해야 합니다.
- 핵심·일별 계산과 목표 계산의 기존 정상 검사도 확인했습니다. 과거 기간 UI/일별 준비 테스트의 5개 실패는 수정 전후 동일합니다. 전체 저장소 테스트가 모두 통과했다고 판단하지 않습니다.
- 운영 DB에 저장·삭제 요청을 보내거나 과거 마감 자료를 임의로 변경하지 않았습니다. 실제 자료 한 날짜의 조회→마감→재열기 확인이 배포 후 필요합니다.

## 적용과 복원

다운로드한 ZIP의 해시를 확인하고 새 임시 폴더에 풉니다. 다음 명령에서 저장소 경로를 사용합니다.

```powershell
node .\apply-cofiring-review-v3.cjs --repo "C:\Users\GSENR\Desktop\gs-shift-log" --apply
```

적용 후 검증:

```powershell
node --test --test-reporter=spec .\tests\project-hardening-v1.test.mjs .\tests\project-access-v2.test.mjs .\tests\project-cofiring-v3.test.mjs
```

문제가 생기면 적용 도구가 출력한 이번 백업 경로로 복원합니다. 설치 이후 해당 파일이 추가 수정되면 덮어쓰지 않고 중단합니다.

```powershell
node .\apply-cofiring-review-v3.cjs --repo "C:\Users\GSENR\Desktop\gs-shift-log" --rollback "이번 설치에서 출력된 BACKUP 경로"
```

복원 명령도 로컬 파일만 복원합니다. 이미 배포했다면 복원된 웹 코드를 별도로 커밋·배포해야 합니다. 서버에 이후 저장한 업무 데이터는 이 명령의 복원 대상이 아닙니다.
