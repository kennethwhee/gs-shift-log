# 유기성 사용량 원본 검증 보완 — 2026-09-24

## 확인한 문제

2026-09-24 화면에 유기성 사용량이 두 호기 모두 10.42톤으로 표시되었다. 화면의 115.39톤은 입고량이며 사용량이 아니다. 실제 사용량은 같은 기간의 시작·종료 재고가 있어야 계산할 수 있다.

기존 화면은 DataPARC 유기성 재고를 받지 못하면 안내만 표시하고 이전 저장 사용량을 남겼다. 그 값을 사용해 종합 혼소율과 계산 완료 상태를 표시할 수 있었다. 저장 사용량을 10.42톤씩 넣고 재고가 없는 보고서를 전달한 DOM 재현에서 동일한 잘못된 계산 경로를 확인했다. 실제 회사 PC에서 10.42가 처음 생성된 시점·원본과 재고 미수신 사유는 아직 확인하지 않았다.

계산 화면에서 비활성화한 오전회의 유기성 자동 입력과 별도로, 과거 날짜의 오전회의 자료를 입력하고 저장하는 이전 보조 스크립트가 index.html에 남아 있었다. 이 스크립트는 입력을 소수 둘째 자리로 반올림하기도 했다.

## 변경

- 유기성 사용량은 같은 조회 기간의 Day·Storage A·Storage B 시작재고 합계 + 입고량 − 종료재고 합계로 계산한다. 기존 50:50 배분 규칙과 소수 넷째 자리 입력 정밀도를 유지한다. 호기별 값은 개별 계측 사용량이 아니라 이 규칙에 따른 배분량이다.
- 재고·입고량·기간 검증 실패 시 유기성 사용량을 미확정으로 표시한다. 저장된 수동 값이나 빈칸의 0톤으로 대체하지 않는다. 확인된 석탄·바이오 값은 표시하고 유기성·종합 혼소율은 확정하지 않는다.
- 일별 입고량은 선택 기간과 출처가 일치하는 완료 하역 조회 응답을 받은 뒤에만 사용한다. 조회 실패·이전 날짜의 지연 응답은 계산에 사용하지 않는다. 기간 지정 모드의 입고량 수기 입력 정책은 유지한다.
- 자동 배분을 계산 전에 적용하여 입력칸·계산값·저장 입력이 일치하도록 한다.
- 재고가 없는 상태의 사용량 저장 및 마감을 막는다. 마감 API도 서버에 저장된 DataPARC 재고와 제출된 입고량으로 다시 계산하고, 호기별 배분이 맞아야 저장한다. 입고량을 운영 DB에서 별도 재조회하는 검증은 이번 변경에 포함되지 않는다.
- 새 마감은 검증 버전 4 및 사용한 재고 수지를 기록한다. 기존 마감 데이터는 수정하지 않으며 조회는 유지한다.
- 이전 오전회의 자동 입력·저장 스크립트의 로딩을 제거하고 공개 빌드에서 제외한다. 원본 파일은 과거 검토 기록을 위해 저장소에 남긴다.
- 현재 배포된 toolbar-v1 디자인을 보존한다.

## 검증

- Node.js 24: 기존 검토 49건 + 유기성 검증 10건, 총 59건 통과.
- 실제 UI 코드와 JSDOM으로 이전 저장값 재사용 재현 및 수정 후 미확정 처리 확인.
- 정상 재고·명시적 0·숫자 형식 오류·음수 수지·날짜 불일치·입고 응답 지연·저장 원자성 확인.
- 서버 번들을 Node 전역이 없는 격리 환경에서 실행해 정상 마감 및 재고 누락 거부 확인.
- 공개 빌드 참조 검사 및 이전 자동 입력 스크립트 제외 확인.
- 패치 설치 도구의 변경 충돌, LF/CRLF, 백업·복원, 중간 실패 복구 검사.

이 검증은 실제 회사 PC의 DataPARC 연결, 운영 DB 수량, 브라우저의 시각적 표시 또는 Windows 프로세스 동작을 검증한 것은 아니다.

## 적용과 원본 확인

프로젝트 전체를 삭제하지 않는다. 패키지 설치 도구는 검토한 파일의 일치 여부를 먼저 검사하고 변경 대상만 자동 백업하여 적용한다. 디자인 등 다른 수정이 들어간 파일은 덮어쓰지 않고 중단한다.

```powershell
node .\apply-organic-review-v4.cjs --repo "C:\Users\GSENR\Desktop\gs-shift-log" --apply
```

설치·검사만으로 웹사이트에 반영되지는 않는다. 대상 파일만 커밋·푸시하고 Cloudflare 배포를 확인해야 한다. 이번 패치는 Agent·PowerShell 작업 파일을 수정하지 않아 Agent 재시작이 필요하지 않다.

배포 후 Ctrl+F5로 새로고침하고 해당 날짜를 재조회한다. 자료가 없으면 `유기성 자료 확인 필요`가 표시되어야 하며 10.42톤이 저장값에서 다시 들어오면 안 된다. 자료가 있으면 재고 상세의 시작 합계 + 입고량 − 종료 합계 및 50:50 배분을 확인한다.

패키지의 `inspect-organic-report.cjs --date 2026-09-24`는 기존 로컬 period-report.json 중 최신 3개에서 재고 수신 여부와 재고값만 읽어 출력한다. 새 조회나 Excel·프로세스·DB·네트워크 작업을 수행하지 않는다. 보고서가 없거나 재고가 누락되어 있으면 실제 사용량 확정을 위해 새 조회의 원본 확인이 추가로 필요하다.

복원:

```powershell
node .\apply-organic-review-v4.cjs --repo "C:\Users\GSENR\Desktop\gs-shift-log" --rollback "설치 결과의 BACKUP 경로"
```

복원은 이번 백업의 파일만 대상으로 하며 적용 이후 추가 수정이 있으면 중단한다. 이 패치는 전체 프로젝트 검토 완료를 뜻하지 않는다. Blower 및 나머지 전체 검토는 별도 진행 대상이다.
