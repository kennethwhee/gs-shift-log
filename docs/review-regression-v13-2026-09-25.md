## 실제 동작 수정

| 경로 | 확인한 문제 | 수정한 동작 |
|---|---|---|
| 혼소율 저장 결과 복원 | 자동 재고 계산으로 생긴 미저장 상태를 사용자 편집으로 판단해, 더 긴 조회가 실패한 뒤 화면을 다시 열어도 마지막 정상 결과를 복원하지 못함 | 자동 갱신과 직접 편집을 구분. 직접 편집은 보호하고 원복 시 편집 상태도 복원. 실패 후 다시 열면 정상 저장 결과의 원래 조회 범위와 값을 표시 |
| 기존 오전회의 선택일 초기화 API | 선택일 초기화가 먼저 전역 만료 처리를 실행해 다른 날짜 요청 상태까지 변경 | 선택일의 기존 대상 종류에만 유효한 오래된 요청 정리를 적용 |
| 현재 오전회의 확인 후 삭제 API | 삭제와 초기화 상태 변경이 별도 쿼리여서 중간 실패나 버전 충돌에 일부 삭제가 남을 수 있음. 잘못된 버전 값은 검사 우회 가능 | 정수 버전·동일 출처 검증. 버전과 진행 중 조회를 트랜잭션 안에서 다시 확인하고, 삭제/상태 변경/건수 조회를 하나의 D1 batch로 처리. 충돌·중간 오류는 전체 취소하고 SQL 내용을 응답에 노출하지 않음 |

초기화 버튼의 기존 확인 창, 대상 데이터 종류 및 사용자 권한 정책은 유지한다.
이 검토/설치 과정에서 운영 DB 삭제나 조회는 실행하지 않는다. 스키마 변경도 없다.
D1 batch의 순차 실행과 전체 롤백 의미는 [Cloudflare 공식 문서](https://developers.cloudflare.com/d1/worker-api/d1-database/#batch)를 기준으로 검증했다.

## 실패 검사 정리 근거

V12 기록의 실패 123건이 모두 서로 다른 제품 오류를 뜻하지는 않았다.
최신 기준 코드의 1,887개 검사 중 123개 실패를 재현하고, 실패 파일·테스트 이름·원인을 기록했다.
Node가 실행할 수 있는 `*.test.js`, `*.test.mjs`, `*.test.cjs`를 모두 검사한다.
PowerShell 파일을 Node 입력 목록에 넣지 않으며, 필요한 PS 검사는 Node에서 PowerShell로 실행한다.

- API를 data URL로 옮겨 상대 import가 깨진 검사 2개는 실제 모듈 URL을 사용하도록 수정했다.
- mounted UI 모형에 실제 사용하는 attribute 조작과 검증된 동일 기간의 재고·입고 응답을 추가했다.
  수동 입력 시험은 명시적으로 수정 모드를 열고, 자동 재고와 다른 값을 시험한다.
- 현재 배포 HTML의 캐시 버전을 과거 날짜 문자열로 고정한 검사는 단일 로더와 비어 있지 않은 버전을 검증한다.
  핵심 로더에는 실제 파일 존재 및 중복 로딩 검사도 추가했다.
- 유기성 자정 재고는 현재 운영 계약인 전날 00:00부터 선택일 00:00까지의 마지막 실제 값으로 검사한다.
  석탄/Bio 1분 경계와 혼동하지 않으며, 경계 전후 시각을 실제 계약 함수로 확인한다.
- Blower 교체의 승인된 대기 RUN, 오전회의 현재 조회 버튼, 최신 안내 문구와 맞지 않는 기대값을 수정했다.
- 전체 Agent/수식 블록의 과거 해시는 이후 기능 추가까지 모두 변경으로 판단했다.
  이를 새 해시로 무조건 갱신하지 않았다. 변경되지 않은 NativeOM/소유권/정리 구간 해시와
  실제 배포 worker/controller의 정확한 바이트 해시는 유지한다.
  실제 PowerShell로 소유 핸들 종료 12가지, 13 TAG × 11개 수식 143개를 실행 검증한다.
  테스트의 프로세스 객체는 모형이며 Excel·DataPARC·실제 프로세스 조작은 없다.
- 열려 있는 일일 DATA 통합문서 발견과 나중에 추가된 숨김 읽기 전용 폴백의 검사 범위를 분리했다.
  전자는 기존 Excel을 열기/저장/종료하지 않으며, 후자는 읽기 전용 열기와 자신이 만든 창의 정리 조건을 별도로 확인한다.
