# 6차 검토 R2: 계정 비밀번호와 최신 Blower 호환

기준: 1~5차 검토와 Blower 기동 대기 RUN V6 적용 상태. 별도 작업에서 추가한 혼소율 사용량 배치 및 BIO 목표 디자인을 유지한다.

R2는 계정 패치를 준비한 뒤 적용된 Blower V6와의 기준 파일 불일치를 해결한다. 최신 Blower API·요청 생성·화면 파일은 검증할 의존 파일로만 취급하며 교체하지 않는다. 지원되는 23개 설비의 기동 대기 중 RUN 조회 정책에 맞춰 이전 검사 1개를 보완하고, 최신 Blower 검사를 기존 계정 검사와 함께 실행한다.

자료: `GS_Shift_Log_Blower_Pending_RUN_v6_20260924.zip`의 모든 대상 파일 해시를 검증했으며, 세 Blower 화면 파일은 현재 공개 배포본과 일치했다. PC·모바일 진입 화면과 혼소율 디자인 기준도 다시 대조했다. 알려지지 않은 파일 변경이 발견되면 모든 쓰기를 중단하는 검증은 유지한다.

## 계정 동작

- 로그인·비밀번호 변경·관리자 비밀번호 재확인의 요청을 D1에서 원자적으로 제한한다. 계정별 5분에 10회, Cloudflare 접속 IP별 1분에 60회이며 성공을 포함한 비밀번호 확인 요청 기준이다. 제한 시 429와 Retry-After를 반환한다. 세션 확인·기존 로그인은 이 제한에 포함하지 않는다.
- 새 계정은 사번 대신 무작위 192비트 임시 비밀번호를 발급한다. 직원 직접 등록·엑셀 등록 완료 시 한 번 표시하며, 서버에는 PBKDF2 해시만 저장한다. 동시에 같은 계정이 등록되어도 실제 저장된 임시 비밀번호만 반환한다. 전달 전 화면을 닫거나 응답을 잃으면 관리자가 다시 발급해야 한다.
- 임시 비밀번호로는 업무용 로그인 세션을 발급하지 않는다. 먼저 비밀번호 설정·변경에서 본인 비밀번호를 정한다. 임시 비밀번호는 변경 또는 재발급 전까지 유효하다.
- 새로 정하는 비밀번호는 15~100자다. 문장·공백을 허용한다. 동일 비밀번호·반복 문자·몇 가지 대표적인 단순 문자열을 거절한다. 유출 비밀번호 전체 목록을 검사하는 기능은 아니다.
- 기존의 별도 비밀번호는 강제로 바꾸지 않는다. 기존 세션도 설치·배포만으로 일괄 해제하지 않는다.
- **사번을 비밀번호로 쓰던 계정은 사번만 알아서는 새 비밀번호를 설정할 수 없다.** 이미 로그인된 본인의 유효한 세션에서 변경하거나, 최고관리자가 발급한 임시 비밀번호로 설정한다. 로그인 중인 최고관리자는 배포 후 로그아웃하기 전에 먼저 본인 비밀번호를 변경하는 것이 좋다.
- 본인 비밀번호 변경에는 현재 비밀번호가 필요하다. 변경과 모든 세션 폐기, 비밀번호 변경 기록 저장을 한 트랜잭션으로 처리한다. 동시 변경·계정 비활성화·서버 오류 시 중간 상태를 저장하지 않는다.
- 최고관리자의 다른 활성 계정 초기화에는 유효한 최고관리자 세션, 본인의 현재 비밀번호, 조회한 대상 계정 버전이 모두 필요하다. 사번·임시 비밀번호를 쓰는 관리자는 먼저 자기 비밀번호를 변경해야 한다. 본인 및 기본 최고관리자(2014081)는 본인 변경 흐름을 이용한다.
- 직원 정보 수정·재등록은 기존 비밀번호를 유지한다. 구형 화면에서는 신규 계정 생성을 거절하여 임시 비밀번호가 표시되지 않고 유실되는 일을 방지한다. 화면을 강력 새로고침하면 된다.
- 비밀번호를 변경한 직후 오래된 비밀번호 검증이 끝나더라도 로그인 세션을 만들 수 없도록 최종 조건을 확인한다. 잘못된 사번·비밀번호·비활성 계정은 동일한 로그인 실패를 반환한다.
- 사용하지 않는 별도 계정 생성 API `/api/create-user`, `/api/employees-seed`는 410을 반환한다. 직원 관리 화면을 사용한다. 한 번만 허용하는 `/api/create-initial-admin`의 설정 키 검증·동시 생성 방어는 유지하며 새 비밀번호 기준을 적용한다.

## 화면

PC와 모바일 로그인 화면 및 로그인 후 상단에서 비밀번호 설정·변경으로 이동한다. 직원 관리에 임시 비밀번호 발급 링크를 추가했다. 비밀번호를 브라우저 저장소·일반 로그에 남기지 않으며, 임시 비밀번호는 전달 확인창을 닫으면 지운다. 실패한 응답을 자동 재전송하지 않는다. 직원 명단 저장 이후 목록 조회만 실패한 경우 저장 완료 사실을 구분해 안내한다.

## 구형 Blower 검사 정리

실제 Blower 제품 코드는 바꾸지 않았다. 이전 정책을 기대하던 검사를 현재 정책과 일치시켰다.

- 일반 이력 편집·삭제는 과거·자동·DataPARC 행을 포함한다. 공개 및 모바일 감시 화면의 쓰기 금지는 유지한다.
- 삭제는 원본 ID를 유지한 숨김 삭제이며, 감사 기록에 삭제 전 행을 보관한다.
- 현재 교체 주기에 영향을 준 이력 변경은 남은 교체·기동 기준으로 돌아가고 누적시간은 RUN 재조회 전까지 미확정이다. 과거 수동 수치를 확정 측정값으로 되살리지 않는다.
- 명시된 최초 기동 이후 범위, 검증된 증분 이어조회, 지원되는 23개 설비 모두의 기동 대기 RUN 조회 정책을 반영한다. 기동 시각을 만들지 않으며 실제 RUN 조회 전에는 시간을 미확정으로 표시한다.
- 브라우저 이벤트 모의 환경과 상대 모듈 import를 보완했다. 조회 API 테스트는 실행 날짜와 무관한 최근 합성 날짜를 사용하며, 오래된 캐시 버전 문자열을 고정하지 않는다.

## 검증과 한계

- 35개 회귀 검사 파일: 781개 통과, 실패·생략 0개.
- 신규 계정 보안 검사: 26개. 실제 SQLite 트랜잭션으로 반복 요청, 동시 변경, 세션 폐기, 실패 시 롤백, 초기 비밀번호 보호를 검증했다.
- 계정 제품 코드는 최초 V6와 동일하다. 최초 V6에서 수행한 jsdom의 실제 HTML 및 브라우저 함수 실행 검사: 10개. PC·모바일 링크, 임시 비밀번호 안전한 출력·삭제, 변경·재발급, 중복 클릭, 응답 유실, 직원 직접·엑셀 등록 순서 확인.
- Cloudflare용 ESM 번들: Node 전용 전역 없이 계정 생성 → 임시 로그인 차단 → 비밀번호 설정 → 로그인·첨부 쿠키 발급 확인. 새 해시는 기존 배포 코드와 같은 PBKDF2-SHA256 100,000회 설정을 유지했다.
- 운영 DB·사용자 계정에 대한 테스트나 실제 비밀번호 변경, OIS·Excel·예약 작업 실행은 하지 않았다. 실제 배포 후 사용자 브라우저 확인은 별도다.

## 배포와 복원

설치기는 파일만 변경하고 `.patch-backup`에 정확한 원본을 남긴다. Git, 배포, DB, 프로세스를 조작하지 않는다. 배포 후 처음 비밀번호 확인 요청이 들어오면 기존 D1 바인딩에 다음 보조 테이블과 만료 인덱스를 준비한다: `auth_attempt_limits_v6`, `auth_change_guards_v6`, `auth_password_audit_v6`. 기존 사용자 테이블 구조나 계정을 일괄 수정하지 않는다. 오래된 `schema.sql`을 운영 DB에 실행하지 않는다.

Cloudflare Pages 빌드 명령은 `node scripts/build-web.mjs`, 출력은 `web-dist`를 유지한다. OIS Agent 재시작은 필요 없다.

파일 복원은 설치기의 `--rollback`으로 가능하다. **파일 복원은 이미 변경된 계정 비밀번호나 DB 상태를 되돌리지 않는다.** 임시 비밀번호 발급 후 이전 로그인 코드로 배포를 되돌리면 그 임시 비밀번호를 처리할 수 없으므로, 운영 복원은 계정 상태와 함께 검토해야 한다.
