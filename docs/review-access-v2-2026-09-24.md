# GS Shift Log 2차 검토 수정 — 접근권한과 계정 처리

기준: 2026-09-24 1차 패치 적용 상태. 사용자가 올린 커밋 `91280cd`의 변경 파일과 원본 소스를 기준으로 비교했다. 이 문서는 2차 수정 범위를 설명하며, 프로젝트 전체 검토 완료를 뜻하지 않는다.

## 수정 내용

### 업무일지와 첨부파일

| 경로 | 허용 범위 |
| --- | --- |
| `GET /api/legacy-logs`, `GET /api/legacy-diaries` | 활성 계정의 유효한 Bearer 세션 |
| `GET /api/legacy-login` | 최고관리자 세션 |
| `POST /api/legacy-import` 단일 날짜·DAY/NIGHT | 로그인한 직원. 기존 선택 근무 동기화 유지 |
| 위 API의 기간·ALL 동기화 | 최고관리자 |
| 과거·신규 첨부파일 읽기 | 유효한 Bearer 세션 또는 해당 파일 경로의 첨부파일 쿠키 |
| 신규 업무일지 읽기 | 기존 Bearer 검증 유지. 성공 시 첨부파일 쿠키 갱신 |

- 인증되지 않은 요청은 업무 데이터 조회, 원격 시스템 호출, R2 접근 전에 차단한다.
- 서버 내부의 과거 일지 호출에도 검증된 Bearer를 전달한다. 전송 대상은 현재 서비스의 `/api/legacy-diaries`이며 리디렉션을 따라가지 않는다.
- 이미지·PDF를 기존 화면에서 직접 열 수 있도록 로그인/세션 확인/일지 읽기 성공 응답에서 첨부파일 전용 쿠키를 발급한다. 두 첨부파일 경로에만 전송되고 `Secure`, `HttpOnly`, `SameSite=Strict`를 설정한다. 저장·삭제 요청은 이 쿠키로 인증하지 않는다.
- 파일 요청마다 서버에서 세션 만료와 계정 활성 상태를 다시 확인한다. URL에 로그인 토큰을 넣지 않는다.
- 로그아웃은 기존 세션 삭제와 함께 두 쿠키를 만료시킨다. 네트워크 연결 없이 서버 로그아웃이 실패하면 서버 세션 해제 여부까지 보장할 수 없는 기존 제약은 남는다.
- 첨부파일 응답은 저장 방지와 스크립트 실행을 제한하는 CSP를 적용한다. 파일명만 알고 있거나 UUID만 알고 있는 익명 접근을 차단한다.
- 과거 첨부파일의 한글 파일명이 HTTP 헤더 오류를 일으키던 문제를 수정했다. `filename*`로 이름을 전달하고 `download=1`도 처리한다.

### 로그인 정보 기억

- PC·모바일의 ‘자동 로그인’ 체크 항목을 ‘사번 기억’으로 변경했다.
- 브라우저의 `gsShiftLog.rememberedLogin`에는 사번만 남긴다. 이전 버전이 저장했던 비밀번호는 새 페이지가 열릴 때 제거한다.
- 기존 유효 세션으로 앱이 바로 열리는 경우에도 이전 비밀번호 저장값을 정리한다. 현재 사용자의 세션 저장 방식과 만료 기간은 변경하지 않았다.
- PC와 모바일 로그인 경로가 같은 작은 공통 모듈을 사용한다. 저장소 접근이 차단되어도 사번 기억 처리가 예외를 일으키지 않는다.

### 직원 계정

- 직원 수정창에 ‘로그인 허용’ 선택을 추가했다. 중지를 선택하면 계정을 비활성화하고 기존 세션을 삭제한다.
- 중지된 계정의 이름·권한 수정이나 엑셀 명단 등록만으로는 계정이 다시 활성화되지 않는다. 수정창에서 허용으로 바꾼 경우에만 명시적인 재활성화 요청을 보낸다.
- 재활성화 시에도 이전 세션을 제거하므로 다시 로그인해야 한다. 기존 비밀번호는 보존한다.
- 직원 삭제 API는 명단 삭제, 계정 비활성화, 해당 직원의 모든 세션 삭제를 하나의 D1 batch로 처리한다. 과거 일지와 사용자 기록을 일괄 삭제하지 않는다.
- 직원 저장도 전체 요청을 하나의 batch로 처리한다. 도중에 실패하면 명단만 저장되거나 계정만 갱신되는 부분 적용을 되돌린다.
- 권한 변경 시 이전 세션을 해제한다. 본인과 기존 기본 최고관리자의 삭제·중지·권한 해제는 차단한다. 직원 엑셀에 본인/기본 최고관리자를 일반 직원으로 지정한 행이 있으면 전체 저장을 거절하므로 해당 행의 권한을 확인해야 한다.

## 검증과 한계

- 1차 13개 + 2차 17개 회귀검사: **30개 통과**. 실제 함수와 메모리 SQLite를 사용했다.
- 익명·만료·비활성·위조 세션, 쿠키 범위, 내부 인증 전달, 한글 파일명, 계정 삭제, 저장 실패 시 rollback, 재활성화, 실제 비밀번호 로그인, 로그아웃, 비밀번호 저장값 정리를 검사했다.
- PC·모바일 실제 함수/요청 표현식을 분리 실행한 **17개 동작 검사 통과**. 화면 렌더링 검사는 아니다.
- 변경 JavaScript와 HTML 내 스크립트 문법 및 공개 빌드의 파일 포함 여부를 확인했다.
- 이 실행 환경에서 브라우저 실행파일을 확보하지 못했으므로 실제 브라우저의 화면·클릭·쿠키 동작은 미검증이다. 운영 Cloudflare D1/R2와 실제 OIS·Excel 작업도 이번 로컬 검사에 포함되지 않았다.
- 프로젝트의 모든 기존 테스트가 통과했다는 의미는 아니다. 전체 테스트와 오래된 테스트 정리는 별도 과제다.

## 적용 후 확인

1. Cloudflare 배포가 성공하면 PC와 모바일 앱을 새로고침한다. 기존에 열린 오래된 탭도 다시 연다.
2. 일반 직원 로그인 → 과거 업무일지 조회 → 과거/신규 이미지·PDF 열기와 다운로드를 확인한다. 다른 브라우저의 로그아웃 상태로 같은 파일 URL을 열면 로그인 오류여야 한다.
3. 일반 직원의 선택 근무 동기화와 최고관리자의 기간 동기화를 각각 확인한다.
4. 관리자 직원 수정창의 로그인 허용/중지 동작은 테스트용 계정으로 확인한다. 중지 후 기존 세션이 차단되고, 허용으로 바꾼 뒤 다시 로그인할 수 있어야 한다.
5. 기존에 요청했던 혼소 실조회와 Log Sheet PDF 생성 확인도 남아 있다. 이번 패키지는 Agent 파일을 변경하지 않으므로 Agent 재시작은 필요하지 않다.

## 이후 남은 전체 검토 과제

- 로그인 시도 제한, 사번과 같은 초기 비밀번호 정책, 여러 API에 흩어진 최고관리자 판정 통합.
- 혼소 마감 자료의 서버 계산/검증, 동시 수정 충돌 처리, 월별 비율 산정 기준.
- 실제 운영 스키마를 기준으로 한 마이그레이션 정리와 요청 중 DDL 제거.
- 대형 PC·모바일 JavaScript/CSS의 중복과 과거 덧붙임 코드 정리.
- 전체 테스트 정비와 실제 PC·모바일·OIS·Excel 업무 흐름 확인.
