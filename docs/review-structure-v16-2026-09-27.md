# Structure V16 — 석회석 사용량 기본 설치 함수 분리

## 범위

확인된 V15 R2 원본은 `607e34a4191f40260e91961c283aa66007650f48` 배포 로그에 대응하는 이전 패키지의 `script.js`입니다. 회사 PC의 최신 파일 전체를 이번 작성 환경에서 직접 읽거나 실행하지는 않았습니다.

`installLimestoneUsageCalculatorFeature` 함수 본문 2,569줄을 `maintenance/limestone-usage-calculator.js`에 그대로 옮깁니다. 원래 즉시 실행식 위치에는 `(0, window.GSLimestoneUsageCalculator.install)();`만 남깁니다. 본문 SHA256(LF)은 `ca5a50985126aaf7f1d86479934338bd8ef2d3136b69bbe5c741f9b81489f5bd`입니다.

함수 밖의 메인 코드, 기존 석회석 OIS·복원 후속 확장, 모바일 런타임, CSS, API, DB, Agent, Controller, Worker, 기존 테스트는 변경하지 않습니다. 석회석 기능 전체를 한 번에 분리하는 작업이 아닙니다.

## 초기화와 의존성

새 파일은 정의만 등록합니다. 원래 위치의 호출이 기존 이벤트·외부 함수 등록 시점을 유지합니다. `DOMContentLoaded`, 즉시 초기화, 중복 설치 방지와 외부 호출 함수 3개는 기존 함수 본문 그대로입니다. `getShiftLogAuthHeaders`, `isLimestoneUsageMobileMonitorMode`는 기존 메인 전역 의존으로 유지합니다.

PC 로더는 새 석회석 정의 → 기존 확대 정의 → 기존 검색 정의 → 메인 순서입니다. V14/V15 URL과 메인 `v`, `limestone`, `closedcards` 값은 그대로 두고 `structure16=20260927-v1` 캐시 키만 추가합니다. 모바일에 새 로더를 넣지 않습니다.

## 기능 보존 기준

시작 재고 + 해당 호기 입고량 − 종료 재고 계산, 빈값과 0 구분, 소수점 두 자리 절삭, 음수 표시, 선택일 저장값 복원, 늦게 도착한 이전 날짜 응답 차단, 명시적 입고량 새로고침의 기존 GET → sync_usage POST 동작을 보존합니다. 이번 단계에서 기존 숫자·날짜·권한 규칙을 새로 설계하거나 강화하지 않습니다.

## 적용 게이트

1. 원래 설치식이 정확한 검토 본문인지 확인합니다. 일치하지 않으면 파일을 쓰지 않습니다.
2. 현재 작업 사본과 실제 커밋 후보를 각각 임시 디렉터리에 만듭니다. 서로 같으면 한 번만 검사합니다.
3. 각 후보에서 기존 전체 테스트와 웹 빌드를 실행합니다. 실패하면 실제 저장소 파일 적용과 커밋·푸시를 하지 않습니다.
4. 검사 중 원본 저장소·인덱스·HEAD가 변경되지 않았는지 재확인한 뒤 5개 대상만 백업·적용합니다.
5. 게시 시 별도 Git 인덱스에 검토 변경만 커밋합니다. 기존 메인·HTML의 대상 밖 작업/스테이징 변경은 보존합니다. 강제 푸시하지 않습니다.

실제 계산 데이터와 로그인된 브라우저 동작, Windows Excel 운전, Cloudflare 배포 성공은 별도 현장 확인 대상입니다. 로컬 모의 DOM 테스트 통과는 이들 실운영 확인을 대신하지 않습니다.

## 확인된 기존 표시 한계

기존 `Math.trunc(value * 100) / 100` 표시 규칙은 자바스크립트의 이진 부동소수점 표현 때문에 `10.12`가 `10.11`로 표시되는 사례가 있습니다. 원본 함수와 동일한 동작이며 V16이 새로 만든 현상은 아닙니다. 구조 분리와 기능 변경을 섞지 않기 위해 이번에는 바꾸지 않았습니다. 테스트에 이 기존 동작을 명시적으로 기록했으며, 표시 규칙 개선은 별도 변경으로 검토해야 합니다.
