# Blower 기동 대기 RUN 조회 복구 V6

기준 소스: `39d75b22c18aad2042485c0e3a51a06a4ad4c7d6` (2026-09-24 원격 main).

## 문제와 변경

업무일지에서 V-Belt 교체를 자동 등록하면 기동 시각이 없는 새 주기는
`pending`이 된다. FBHE/Seal Pot에만 적용되던 RUN 조회 예외 때문에
Bag Filter/Silo/유기성/축분 설비는 실제 운전 중이어도 개별 조회와 전체
최신화에서 제외되었다. 카드도 기동 이력의 부재를 운전 상태로 표시했다.

- 지원되는 23개 설비 모두 수동 기동 등록 없이 교체 이후 RUN 조회가 가능하다.
- 현재 운전 상태와 누적시간은 성공한 RUN 조회의 종료 상태와 RUN=1 누적초로 반영한다.
- 조회 전에는 `RUN 미확인`을 표시한다. 저장된 과거 기동 플래그만으로 운전 중이라고 표시하지 않는다.
- 기동 이력이 없어도 검증된 RUN 조회 결과를 카드·전체 현황·이력에 표시하고 다음 최신화의 증분 기준으로 사용한다.
- 교체 이력, 교체일, 원본 업무일지, 수동 기동 시각은 수정하거나 만들어 내지 않는다.
- RUN TAG 확인, 교체 이전 기간 금지, 최대 조회 기간, 요청 소유자 확인, 이력 Revision 검사,
  중복 반영 방지 및 트랜잭션 처리는 유지한다. 조회 중 이력 변경은 충돌로 거절한다.
- 기존 Agent의 `legacy|started` 통신 형식을 재사용한다. Agent/Excel 파일 및 DB 스키마 변경은 없다.

## 검증

새 회귀 검사 32개와 기존 관련 검사를 포함해 **22개 검사 파일, 458개 통과, 실패 0개**.
실제 제품 코드의 요청 생성 → Agent 요청 파싱·결과 정규화 → 결과 완료 →
이력 반영 → 조회 화면 데이터 → 증분 최신화 경로를 메모리 SQLite로 실행했다.
숫자 결과는 합성 자료이며 회사 DataPARC에 접속한 실운전 검증은 아니다.

검증에는 23개 설비의 pending 조회, #2 Bag Filter B 연속 RUN,
RUN=0, 전체 최신화 일괄 요청, 증분 합산, 같은 요청 재반영,
조회 중 교체/기동/수동값 변경, 카드·전체 현황·이력 표시가 포함된다.

별도 V5 전체 검사 모음은 394개 중 393개 통과했다.
`project-hardening-v1.test.mjs`의 혼소율 worker 파일 해시 검사 1건은
수정 전 `39d75b2`에서도 동일하게 실패했다. 해당 혼소율 파일은 이번 변경에 포함하지 않았다.

## 적용 및 현장 확인

패키지의 설치기는 기준 파일 내용과 SHA-256이 맞을 때만 대상 파일을 교체한다.
LF/CRLF 차이는 허용한다. 다르게 수정된 대상 파일이 있으면 쓰기 전에 중단한다.
원래 파일은 `.patch-backup`에 보관하며 무관한 로컬 수정은 유지한다.
개별 적용·검사 명령은 Git 작업을 하지 않는다. 통합 설치기에 `--publish`를 지정하면
현재 main과 원격 main이 같은지 먼저 확인하고, 적용·검증 후 대상 9개 파일만 커밋·푸시한다.
기존 staged 변경이나 서로 다른 커밋이 있으면 설치 전에 중단한다. 강제 푸시·자동 병합은 하지 않는다.

1. `apply-blower-pending-run-v6.cjs --repo 프로젝트경로 --apply` 실행.
2. `verify-blower-pending-run-v6.cjs --repo 프로젝트경로` 실행.
3. 변경 파일을 커밋·푸시하고 Cloudflare 배포 성공 확인.
4. 브라우저에서 Ctrl+F5 후 #2 Bag Filter B → 이력 보기 → DataPARC 기간조회.
5. 기존 교체 시각 이후로 조회. 화면의 RUN TAG가 실제 설비의 확인된 1/0 신호인지 유지한다.
6. 현재 RUN=1이면 기동중과 누적시간 표시, 이후 전체 최신화에서 증분 누적 확인.

9월 22일 교체가 해당 설비의 실제 작업이 맞는지는 별도 원문 확인 대상이다.
이 패치는 해당 이력을 임의로 삭제하거나 이전 교체일로 되돌리지 않는다.

복구: `apply-blower-pending-run-v6.cjs --repo 프로젝트경로 --rollback 설치시출력된백업경로`.
설치 후 대상 파일에 추가 수정이 있으면 덮어쓰지 않고 중단한다.
