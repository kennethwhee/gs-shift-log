# 야간 TO 전력 입력 V1 — 2026-09-27

## 동작
- 보직현황의 선택 근무가 NS이고, 같은 날짜 NS/TO 업무일지의 서버 저장 작성자와 로그인 사번이 같을 때만 TO 카드 오른쪽 위에 [전력 입력] 표시.
- 특정 이름(이용수 등)에 고정하지 않음. 주간 및 다른 담당자에게 버튼을 표시하지 않음. 관리자 권한만으로 예외 허용하지 않음.
- 먼저 해당 N/S TO 업무일지를 서버에 임시저장 이상으로 저장해야 담당자를 식별할 수 있음. 업무일지에 작성자가 없는 미작성 카드에는 입력 버튼 없음.
- 시계가 밤인지 판단하는 기능이 아님. 화면에서 선택한 근무 구분 NS를 기준으로 하므로 과거 N/S 실적 정정 가능.
- 실적 기준일은 선택한 NS 근무 시작일로 고정. 예: 9/26 19:00~9/27 07:00 근무의 실적 기준일은 9/26. 날짜 변경은 메인 화면 근무일자에서 수행.
- 발전량, 수전량, 송전량, 태양광 발전량 네 항목 모두 kWh. 빈칸은 미입력이며 실제 0은 유효. 0 이상 숫자 및 올바른 천 단위 쉼표 입력 허용.
- 오전회의자료의 같은 날짜 전력 카드에 TO 저장값 우선 적용. 저장값이 없으면 기존 조회값 유지. 조회 오류 시 오래된 전력 숫자를 보여 주지 않고 재조회 필요 표시.
- 전력 카드 재조회는 TO 저장자료 GET만 수행. Excel·Agent·DataPARC 요청을 생성하지 않음. 증기 및 다른 카드의 조회 동작은 변경하지 않음.
- 최종 엑셀 생성 전에 같은 날짜 TO 저장값을 다시 확인. 발전/송전/수전은 기존 함수에서 kWh→MWh 변환 유지. 태양광 일일은 기존 kWh 유지. 월/연 누적, 증기, 유기성 값 및 수식 보존.

## 저장·권한
- 신규 경로 /api/to-night-power, DB 바인딩 DB 및 기존 shift_log_sessions/users/shift_logs 스키마 사용.
- GET은 조회 전용이며 새 테이블을 생성하지 않음. 최초 허가된 저장 때 to_night_power_daily와 to_night_power_audit 두 테이블을 추가 생성.
- 기존 업무일지, OIS 결과, 혼소 마감자료는 수정하지 않음. 별도 전력 자료는 기존 자동수치 이력 화면에 새 열로 추가하지 않음.
- 로그인 세션과 작성 사번은 서버에서 확인. 저장 트랜잭션에서 세션, 최신 NS/TO 작성자·업무일지 revision 및 전력 revision을 재검사.
- 전력 자료와 변경 이력을 하나의 D1 batch로 저장. 갱신 충돌 시 전체 저장 차단. 화면 입력값을 보존하고 명시적인 다시 불러오기 후 재저장.
- 오전회의 선택일 초기화가 활성화된 동안 TO 값의 화면/엑셀 재표시도 억제. 별도 전력 원본 및 이력은 삭제하지 않음. 기존 초기화 플래그가 해제된 뒤에는 저장된 전력 원본을 다시 조회할 수 있음.

## 검증 범위와 한계
- 저장 API를 Node의 실제 SQLite에 연결한 D1 모의 어댑터로 검증. Cloudflare 실운영 D1에 연결한 시험은 아님.
- API 64건, 실제 script.js 발췌를 사용한 연동/근무일자/엑셀 셀값 검증 14건, Chromium의 모의 API 화면 조작 28건을 별도 수행.
- Chromium 화면은 실제 클래스·ID와 신규 모듈을 사용하는 검증용 최소 화면. 전체 운영 페이지를 실제 계정으로 접속해 시험하지 않음.
- 배포 스크립트는 실행한 PC의 저장소에서 대상 구문과 신규 테스트를 다시 확인하고 실제 웹 빌드를 수행한 뒤 이 패치만 커밋·push.
- Node 내장 node:sqlite가 필요하므로 Node 22 계열의 지원 버전 이상 사용. 내장 모듈 확인에 실패하면 파일 변경 전 중단.
- 제공 시점에는 사용자 PC 파일, GitHub 또는 실제 사이트를 변경하지 않음.

index.html의 로더/캐시 키, script.js의 네 연동 지점, 신규 API/JS/CSS 및 신규 테스트/문서만 대상.
큰 script.js 전체를 제공본으로 덮어쓰지 않고 일치하는 구문만 치환. 혼소·Blower·오전회의 마감 연동 등의 독립된 로컬/스테이징 변경 보존.
일치하지 않는 버전, 부분 적용, 다른 파일의 동시 변경 또는 Git 상태 충돌 시 중단. reset/stash/강제 push 없음.
