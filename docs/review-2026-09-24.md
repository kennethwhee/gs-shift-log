# GS Shift Log 전체 검토 보고서

**검토일: 2026-09-24 · 대상: 사용자가 제공한 `gs-shift-log(4).zip` · 결과: 안정화 및 보안 보완이 필요한 운영 개발본**

## 1. 종합 판단

기능의 범위는 충분히 넓습니다. 업무일지 작성·조회·결재, 점검일지, 효율팀 자료, Excel/OIS 연계, 혼소율, Blower 이력, 입고·반출 관리까지 연결되어 있습니다. 특히 데이터 조회 결과의 검증, 요청 소유권, 일부 동시 수정 방지, 불완전한 센서값 처리에는 상당한 보호 로직과 테스트가 있습니다.

그러나 지금 상태를 ‘완성본’이라고 판단하기는 어렵습니다. **서버 인증 누락, 실제 수치 표시 오류, 실행 파일 간 규칙 불일치, 재설치가 불가능한 DB 초기화 문서, 누적된 화면 패치와 실패한 테스트**가 함께 존재합니다. 새 기능을 늘리는 것보다 현재 기능을 안정된 기준으로 고정하는 작업이 우선입니다.

이번에는 전체 구조와 주요 실행 경로를 검토하고, 명확하게 재현되는 일부 문제를 수정한 **검토용 수정 패키지**를 만들었습니다. 원본 ZIP은 보존했습니다. 수정 패키지는 운영 서버에 적용하거나 Git에 커밋·푸시하지 않았습니다. 운영 환경에 남아 있는 문제까지 모두 해결한 최종 배포본은 아닙니다.

## 3. 가장 먼저 처리해야 할 문제

### P0-01. 로그인 없이 직원 생성·권한 변경 가능 — 이번 수정에 포함

- 위치: `functions/api/employees.js`의 GET/POST/DELETE.
- 원인: 화면에서는 최고관리자 여부를 확인하지만 API에는 세션·권한 확인이 없었습니다.
- **재현:** 외부 네트워크 없이 동일 코드를 메모리 DB에 실행했을 때, 인증 헤더 없는 POST로 최고관리자 계정이 생성되고 HTTP 201이 반환됐습니다.
- 영향: API에 접근할 수 있는 환경이면 화면을 거치지 않고 직원·로그인 계정을 만들거나 변경할 수 있습니다. 실제 운영 사이트의 별도 접근제어 유무는 확인하지 않았습니다.
- 수정: DB의 유효한 세션을 검증하고, 변경·삭제는 최고관리자만 허용했습니다. 효율팀의 팀장 선택 등에 필요한 조회는 로그인 사용자에게 허용했습니다. PC·활성 모바일 코드의 직원 조회·일괄 등록 요청에도 인증 헤더를 연결했습니다.
- 검증: 무인증 거부, 일반 사용자의 관리자 필드 위조 거부, 만료·비활성 세션 거부, 관리자 정상 저장 및 기존 비밀번호 보존 통과.

### P0-02. 최초 관리자 API가 보호되지 않고 관리자 표기도 불일치 — 이번 수정에 포함

- 위치: `functions/api/create-initial-admin.js`.
- 원인: 초기 생성 비밀키 검증이 없고, 기존 계정 검사에 `superadmin`만 사용하여 일반적인 `super_admin`을 놓쳤습니다.
- **재현:** `super_admin` 계정이 이미 있는 메모리 DB에서도 인증 없이 두 번째 관리자 생성이 성공했습니다.
- 수정: 기존 `USER_SETUP_KEY` 체계를 사용하도록 제한했습니다. 32자 이상의 설정 키와 요청 헤더가 일치해야 하며, 관리자 표기·기존 초기 생성 표식·기존 고정 관리자 정책을 함께 확인합니다. 한 SQL 문장의 조건부 INSERT로 동시 생성 경쟁도 막았습니다. 잘못된 JSON은 400, 서버 오류는 내부 정보를 숨긴 500으로 응답합니다.
- 검증: 비밀키 누락/오류 거부, 관리자 표기 2종 차단, 동시 요청 2건 중 정확히 1건 생성 확인.
- 운영 영향: 기존 로그인 계정은 변경하지 않습니다. 기존 관리자가 있는 환경에서는 이 초기 생성 API가 필요하지 않습니다.

### P0-03. 과거 업무일지 API에 인증 공백 — 추가 수정 필요

- 위치: `legacy-login.js`, `legacy-diaries.js`, `legacy-logs.js`, `legacy-import.js`, `legacy-attachment.js`.
- 확인: 로그인 세션을 검사하지 않는 조회·가져오기·다운로드 경로가 있습니다. `legacy-diaries`는 서버에 설정된 과거 시스템 계정으로 원본을 조회하고, `legacy-import`는 이를 DB와 파일 저장소에 기록합니다.
- 영향: 배포 환경이 외부 접근을 허용하면 과거 기록 열람뿐 아니라 인증 없는 가져오기 실행도 가능합니다.
- 조치: 조회는 사용자 세션, 가져오기는 관리자 또는 별도 범위 제한 서비스 인증으로 통일해야 합니다. `legacy-import`가 내부적으로 호출하는 `legacy-diaries` 요청과 PC/모바일 호출자도 함께 수정해야 합니다.
- 이번 상태: 경로만 차단하면 기존 가져오기·이미지 조회가 깨질 수 있어 호출 흐름을 포함하는 별도 수정 항목으로 남겼습니다. 운영 API를 호출해 공격 여부를 확인하지 않았습니다.

### P0-04. 실설정·세션·진단 자료가 소스와 함께 묶임 — 배포 출력 분리, 노출 확인은 별도

- 첨부본에는 실제 OIS 로그인 설정, Agent 인증 설정, 로그인 세션, 진단 로그 및 화면이 포함되어 있습니다. 비밀 값은 이 보고서와 수정 패키지에 복사하지 않았습니다.
- 저장소 루트를 그대로 웹 출력으로 쓰면 백업·진단·로컬 도구가 배포 대상에 섞일 수 있습니다. 실제 Pages의 출력 경로와 공개 여부는 첨부 파일만으로 확정할 수 없습니다.
- 수정: 공개 웹 자산만 선택하는 `scripts/build-web.mjs`를 추가했습니다. 출력에는 Agent 설정·세션·서버 소스·백업·테스트·진단 로그를 넣지 않습니다.
- 남은 조치: 실제 배포 설정 및 이 ZIP의 공유 범위를 확인하고, 노출된 범위가 있다면 해당 로그인 정보·Agent 키·세션을 갱신해야 합니다. 무작정 모든 설정을 삭제하면 회사 PC의 조회가 멈추므로 실제 설정은 별도 보관해야 합니다.

| 번호 | 확인 내용 | 판단과 조치 |

| A05 | OIS/Excel/PDF가 회사 PC의 Windows 상태에 의존 | 예약작업·자동실행·수동 실행의 중복, 장기 실행 PDF, 여러 Excel PID, 보안 제품 검사, COM/NativeOM 응답을 해당 PC에서 검증해야 합니다. 이 ZIP만으로 현재 PC 장애 원인을 단정할 수 없습니다 |

보존한 요소: 첨부본의 Multi-NativeOM 개선, 유휴 폴링 10초 변경, 열린 파일 탐색의 대부분, 요청 소유권·완료 검증·결과 전달 재시도 로직. 이번 패키지는 관련 없는 Agent 변경을 이전 커밋으로 되돌리지 않습니다.

회사 PC 검증은 다음 순서가 적절합니다.

1. Excel이 전혀 없는 상태, 해당 월 파일 1개가 열린 상태, 서로 다른 Excel 인스턴스 2개 상태를 각각 확인합니다.

3. 성공·실패·시간 초과·사용자 취소를 각각 실행해 사용자 파일이 보존되는지 확인합니다.
4. 월 변경, 동일 이름 파일의 복수 경로, Agent 재기동 직후를 확인합니다.
5. 요청 발견 → Excel 연결 → 데이터 취득 → 정리 → 서버 저장 → 화면 표시 시간을 나누어 측정합니다.

권장 사용자 흐름은 다음과 같습니다.

- 조회 상태는 `대기 → 요청 접수 → PC 조회 → 서버 저장 → 완료`로 통일하고, 실패 단계와 재시도 가능 여부를 같은 위치에 표시합니다.

- ‘현재까지’, ‘하루 완료’, ‘마감 저장’을 구별하고, 수동 변경·미수신·빈값을 실제 0과 다른 표기로 유지합니다.
- 기술 버전명·진단 로그·세부 계산 기준은 관리자 진단 또는 상세 보기로 이동합니다.
- 모바일의 조회 전용 정책은 버튼 숨김뿐 아니라 서버 동작과도 일치시킵니다.
- 기본 글자 크기·단위·소수점·강조색·표 높이를 공통 규칙으로 정합니다.

## 9. 불필요한 내용의 정리 기준과 이번 결과

### 배포 대상에서 제외한 항목

공개 웹 빌드에는 실제 실행에 필요한 화면·계산 코드·서식·이미지만 포함합니다. 백업, 진단, 회사 PC Agent, 세션, 의존성 설치본, 테스트, 과거 패치 배포 폴더, 서버 소스는 제외했습니다. `functions/`는 Cloudflare가 서버 코드로 처리하도록 프로젝트 루트에 유지합니다.

현재 화면에서 참조되지 않는 구버전 브라우저 파일 23개도 웹 출력에서 제외했습니다. 예: 모바일 runtime v13, 혼소율 초안, 구버전 가로 기준표 v1~v3, 구버전 상세표 v2~v5, 과거 Organic 자동 연동 장식 파일. 다시 참조되는 경우 빌드가 실패하도록 검사를 넣었습니다.

**주의:** 이 파일들이 소스·테스트·복구에도 불필요하다는 뜻은 아닙니다. 일부는 과거 검사나 호환 분석에 사용되므로 원본 소스에서 무작정 삭제하지 않았습니다.

### 다음 정리 시 보존할 항목

- 실제 설정과 세션은 공개 파일에서 분리하되 회사 PC 운영에 필요한 것은 보호된 위치에 보관합니다.
- 운영 DB·R2, 원본 Excel, 수동 정정 이력, 결재 기록, 자동조회 원본은 삭제 대상이 아닙니다.
- 로그는 보존 기간·최대 크기를 정해 순환 보관합니다. 현재 장애 분석에 필요한 최신 로그는 남깁니다.
- 버전관리 대상에 이미 들어간 의존성 180개 파일·백업 계열 44개 파일·로그 계열 12개 파일·과거 패치 폴더 계열 31개 파일은 별도 정리 후보입니다. ignore 규칙 추가만으로 기존 추적 파일이 없어지지는 않습니다.
- 패치 백업만 약 146.03 MiB입니다. 복구 확인 뒤 외부 보관본을 만들고 운영 작업 폴더에서 분리하는 편이 좋습니다.

## 11. 이번 패키지 적용 및 되돌리기

수정 패키지는 원본 ZIP 전체의 교체본이 아닙니다. 수정 대상 파일과 적용 도구만 포함합니다. 원본 ZIP에 있던 실제 비밀 설정·세션·진단 이미지는 포함하지 않습니다.

1. ZIP을 별도 폴더에 풉니다.
2. 저장소 경로를 지정해 먼저 검사합니다.

```powershell
node .\apply-review-patch.cjs --repo "C:\Users\GSENR\Desktop\gs-shift-log"
```

3. 모든 대상이 첨부 원본과 일치하거나 이미 수정된 버전인 경우에만 적용할 수 있습니다.

```powershell
node .\apply-review-patch.cjs --repo "C:\Users\GSENR\Desktop\gs-shift-log" --apply
```

4. 파일이 다르면 전체 적용 전에 중단합니다. 최신 작업을 덮어쓰지 말고 해당 차이를 다시 병합해야 합니다. 관련 없는 파일은 건드리지 않습니다.
5. 적용 도구는 백업을 만들고 완료 시 경로를 표시합니다. 문제가 생기면 표시된 백업 경로로 되돌릴 수 있습니다.

```powershell
node .\apply-review-patch.cjs --repo "C:\Users\GSENR\Desktop\gs-shift-log" --rollback "표시된 백업 경로"
```

6. 그 후 `node --test tests/project-hardening-v1.test.mjs`로 수정 검사를 실행합니다. 테스트는 Node.js 24.19.0 환경에서 검증했습니다. 회사 PC의 Node 버전이 다르면 내장 SQLite 지원을 먼저 확인해야 합니다.
7. 이 도구는 배포·Git 커밋·푸시·DB 변경·Agent 재시작을 수행하지 않습니다. 실제 웹 출력 설정과 배포 후 기능 검증이 남습니다.

## 12. 확인 근거와 외부 문서

판정의 주 근거는 첨부된 실제 코드·설정 구조와 로컬 재현 결과입니다. 서버 보안 취약점은 제공된 코드 기준으로 판정했으며 실제 공개 사이트의 추가 인증 계층은 확인하지 않았습니다. 일부 화면·Agent 이슈는 현장 검증이 필요한 후보로 구분했습니다.

- Cloudflare Pages build output: https://developers.cloudflare.com/pages/configuration/build-configuration/
- Cloudflare Pages Functions는 프로젝트 루트의 `functions/` 사용: https://developers.cloudflare.com/pages/functions/get-started/
- Cloudflare Pages 정적 헤더와 Functions 응답 적용 범위: https://developers.cloudflare.com/pages/configuration/headers/
- PowerShell 자동 변수 및 PID: https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_automatic_variables

보고서의 파일·함수명은 첨부본 및 이번 수정본을 기준으로 합니다. 줄바꿈과 후속 수정에 따라 줄 번호가 달라질 수 있어 파일·함수·경로를 우선 식별자로 사용했습니다.
