# Blower 조회·저장 안정성 검토 — 2026-09-24 V5

## 수정 내용

- 늦게 도착한 이전 조회가 최신 운전시간·이력·서버 기준시각을 덮어쓰지 않도록 조회 순서를 확인한다. 로그인 세션이 바뀐 뒤 도착한 응답도 반영하지 않는다.
- 이력 변경 요청 전후의 조회를 구분한다. 저장 중의 중간 결과와 저장 이전 결과는 화면에 적용하지 않는다. 저장 응답이 유실된 경우에도 이전 조회를 다시 표시하지 않는다.
- 화면 조회와 수정 작업의 대기 상태를 분리한다. 이전 조회가 끝나도 진행 중인 수정 작업의 버튼을 풀지 않으며, 새로운 조회가 끝난 뒤 오래된 조회 때문에 계속 잠기지 않게 한다.
- 명시적인 교체운전 동기화 후에는 저장 결과를 다시 조회한다. 이전 조회가 이미 무효화됐다면 그 조회에서 자동 동기화를 시작하지 않는다. 저장 요청 자체를 자동 반복하지 않는다.
- 이력 수정이 완료된 뒤 재조회만 실패하면, 닫힌 편집 창 대신 화면 안내와 알림에 “수정 완료·재조회 필요”를 표시한다.
- Blower API의 예상하지 못한 조회·저장 오류는 일반 안내로 반환한다. 내부 예외 내용은 응답에 넣지 않는다. JSON 객체가 아닌 저장 본문은 업무 쿼리·스키마 처리 전에 400으로 거절한다.
- 기존 연속 수정·삭제 검사에 빠져 있던 브라우저 이벤트 등록 모형을 보완했다. 페이지의 Blower 스크립트 버전을 갱신했다.

## 검증

최초 재현 검사 13개 중 수정 전 11개가 실패했고 수정 후 통과했다. 쓰기 응답 유실·엄격한 재조회·동기화 중 조회·일반 조회 실패 검사를 추가하여 새 검사 총 17개를 통과했다.

패키지의 `verify-blower-review-v5.cjs --repo 프로젝트경로`는 22개 검사 파일을 실행한다. 이 환경에서 **394개 통과, 실패 0개**를 확인했다. 여기에는 1~4차 검사 59개, 새 검사 17개, 이력 수정·삭제·오래된 버전 충돌·수동 정정 유지·23개 설비 DataPARC 요청·최신화·예약 검사 등이 포함된다. 공개 빌드에서 비공개 소스와 설정이 제외되는 기존 검사도 포함한다.

Blower API를 브라우저용 ESM으로 묶어 Node 전역 객체가 없는 환경에서 실행했다. 인증 없는 쓰기 401, 잘못된 본문 400, 예기치 않은 오류 500의 응답과 내부 오류 비노출을 확인했다.

조회 순서 검사는 실제 UI의 조회·저장 함수를 실행하고, 합성 응답을 지연시켜 순서를 바꾸는 방식이다. SQLite 검사는 메모리 DB를 사용한다. 운영 DB·실제 Agent·DataPARC에는 검사 요청을 보내지 않았다.

## 기존 검사와 남은 검토

저장소의 모든 과거 검사를 통과했다는 의미는 아니다. 별도 비교한 이전 검사 모음은 수정 전 368개 중 65개, 수정 후 62개가 실패했다. 보완한 브라우저 모형으로 3개가 해결됐으며 새로 실패한 항목은 없다. 기존 실패에는 `window.addEventListener` 누락, 상대 import를 해석할 수 없는 data-URL 검사, 과거 캐시 버전 고정, 자동 이력 삭제 금지 등 현재 정책과 다른 기대가 포함된다.

기존 `blower-fbhe-seal-run-reconcile.test.mjs`도 기준 소스와 수정 소스 양쪽에서 동일한 41개 실패가 있었다. 조회 시작일·출처 검증·날짜 범위·화면 문구의 기대를 현재 계약과 대조하여 별도로 정리해야 한다. 해당 실패를 새 패치의 통과 수에 포함하거나, 검사를 통과시키기 위해 운전시간 계산 규칙을 바꾸지 않았다. 비교 결과는 패키지의 `verification.json`에 기록했다.

배포 후 실제 PC에서 이력 수정 → 이력 다시 열기 → 최신화의 동작과, 모바일에서 조회 기능을 확인해야 한다. 본 검토만으로 실제 OIS/Excel/PDF 연동이나 프로젝트 전체의 완성을 확인한 것은 아니다. 구형 검사 정리, 로그인 시도·초기 비밀번호 정책, 스키마 초기화 정리, 중복·미사용 화면 자산, 실제 PC·모바일·OIS·PDF 통합 확인은 후속 범위로 남는다.

## 설치·복구

설치기는 검토한 파일의 내용이 일치할 때만 6개 파일을 적용하고, 원래 바이트를 `.patch-backup`에 보관한다. LF/CRLF 차이는 허용하되 내용이 다른 사용자 변경은 덮어쓰지 않는다. 확인만 하려면 `--apply`를 생략한다.

```powershell
node "패치폴더\apply-blower-review-v5.cjs" --repo "C:\Users\GSENR\Desktop\gs-shift-log" --apply
node "패치폴더\verify-blower-review-v5.cjs" --repo "C:\Users\GSENR\Desktop\gs-shift-log"
```

복구는 설치 출력의 실제 BACKUP 경로를 사용한다. 설치 후 파일을 추가로 수정했으면 복구기가 중단하므로 해당 변경을 먼저 확인해야 한다.

```powershell
node "패치폴더\apply-blower-review-v5.cjs" --repo "C:\Users\GSENR\Desktop\gs-shift-log" --rollback "출력된 BACKUP 경로"
```

로컬 설치는 Git 커밋·푸시·배포·DB 작업·프로세스 재시작을 실행하지 않는다.
